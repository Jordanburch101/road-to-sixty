# App demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the home page's still app picture with a looping, animated demo of the app's first run and of the app at work (#60).

**Architecture:** The whole story is a pure function of time, `demoAt(t)`, in a plain TypeScript file with tests. One React island, `AppDemo`, renders the state for the current time. CSS transitions do all the movement between states, so the island only advances the clock. The page's HTML (and reduced motion, and no scripts) shows a fixed still state.

**Tech Stack:** Astro 7 (static), `@astrojs/react` with `client:visible`, React 19, Tailwind 4, `packages/ui` (theme, `Button`, `Fog`, `compass.png`, class icons), `bun test`.

**Spec:** `docs/superpowers/specs/2026-10-20-app-demo-design.md`. Read it first: its tables are the source for every time, word and value below.

## Global Constraints

- React is sent to the browser for this island only. Everything else on the site stays rendered at build time.
- No fonts, scripts or images from other sites. No cookies. Nothing that counts visitors.
- Icons and the cursor are raster art (PNG), never drawn SVG.
- Blue (`accent`) is only for sync status, the setup tick and the lit fog. The main action on a screen is the cream button.
- Comments: plain sentences that explain why, only where the code can't say it. British spelling (colour, centre).
- Commit subjects: `Web: what changed (#60)`, with a body for anything non-trivial, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Made-up data only: Player#0000, PCs "Desk" and "Laptop", the characters in the spec.
- The window is 400 × 640 at every width (narrower only where the screen is under 400 px plus padding). The still picture is the same size.
- Commands run from `apps/web`: `bun test`, `bun run typecheck`, `bun run build` (needs `.env` copied from `.env.example`, with any https values).

## Review Focus

1. **Hydration:** the first client render must match the HTML exactly, so React doesn't throw away the markup. `AppDemo` renders `STILL` first and starts the clock only in an effect. Task 3 checks there are no hydration warnings in the browser console.
2. **Leaving and coming back:** a hidden tab or a demo scrolled away pauses, and when it comes back it carries on without racing through the steps it missed. `advance` clamps each frame's step (Task 1 test `a long gap between frames moves the clock at most 0.1 s`).
3. **Reduced motion switched on while the page is open:** the demo goes back to the still picture and stops. Task 3 listens for changes to the media query, and a manual check covers it.
4. **Narrow phones (320 px):** the setup screen's steps wrap and must still fit in 640 px, with nothing cut off. Task 4 screenshots at 320 px as well as 390 px.
5. **Rising into view:** the section rises in (`data-reveal`) while it's still invisible, so the demo must not use up its first steps before anyone can see them. It starts only once at least half of it is on screen (Task 3's observer, `threshold: 0.5`), and it begins by closing the still window.

```ts
export type Part = "setup" | "arrive" | "level" | "new";
export type Line = { head: string; text: string };
export type Target = "icon" | "install" | "link" | "done";
export type Row = { name: string; cls: "WARRIOR" | "HUNTER" | "PALADIN" | "MAGE"; colour: string; level: number; played: string; line: string; glow: boolean };
export type Step = "waiting" | "current" | "done";
export type Demo = {
  part: Part;
  open: boolean;              // the window is showing
  lit: boolean;               // the menu bar icon is lit
  clock: string;              // "Tue 21:44"
  screen: "setup" | "characters";
  steps: [Step, Step, Step];
  installed: boolean;         // step 1 reads "Addon installed" and the card "Addon 1.10.2"
  typed: string;              // the name box, "" to "Desk"
  linked: boolean;            // "Linked to Player#0000." shows
  cursor: { shown: boolean; at: Target; down: boolean };
  syncing: boolean;           // the pill says "Syncing…" (else "Synced just now")
  pulse: number;              // goes up by one each time the pill turns to synced, so the dot can pulse once
  rows: Row[];                // top to bottom
};
export const LOOP: number;    // seconds, 23
export const LINES: Record<Part, { left: Line; right: Line }>;
export const STILL: Demo;     // the still picture
export const STILL_LINES: { left: Line; right: Line };
export function demoAt(t: number, phone: boolean): Demo;   // t in seconds, wrapped by LOOP
export function advance(t: number, frameMs: number): number; // the next time, frames clamped to 100 ms
```

- [ ] **Step 1: The player.** In `AppDemo`, state is `t: number | null`, where `null` means the still picture, which is also the first render. In an effect, if `matchMedia("(prefers-reduced-motion: reduce)")` doesn't match, watch the section with an `IntersectionObserver` (`threshold: 0.5`). The first time half of it is on screen, set `t = LOOP - 1` (the window closing), then run a `requestAnimationFrame` loop that sets `t = advance(t, frameMs) % LOOP`. Stop the loop while the section is less than half on screen or `document.hidden`, and carry on from the same `t`. If the reduced-motion query starts matching, set `t` back to `null` and stop. `phone` is `matchMedia("(max-width: 767px)")`, matching Tailwind's `md`. Render `t === null ? STILL : demoAt(t, phone)`, with one exception. Until the clock first wraps past `LOOP`, render `{ ...STILL, open: false, lit: false }`, so the still picture's own rows close with the window instead of switching to the loop's last rows at the same moment. The lines are `STILL_LINES` when `t` is null, else `LINES[demo.part]`.
- [ ] **Step 2: Movement is CSS.** Every change in `Demo` must move. Use transitions keyed off the state:
  - **Window open and close:** opacity plus `scale(0.96)` to `1`, with `transform-origin` at the icon, about 350 ms.
  - **Screen change:** the setup screen goes out with `translateX(-24px)` and a fade, while the Characters screen comes in from `24px`. Both stay mounted, positioned on top of each other.
  - **Steps opening and folding:** the `grid-template-rows: 0fr` to `1fr` transition on a wrapper, about 300 ms.
  - **Text changes** (titles, the card's addon line, the pill, the lines beside the window, character lines): crossfade by stacking the old and new text and fading between them, or by keying a span so it fades in.
  - **Tick:** a keyframe that grows to 1.15 and settles at 1.
  - **Level and played time:** roll by sliding the old number up and out as the new one slides in.
  - **Row arriving:** the same `0fr` to `1fr` wrapper plus a rise and fade, so the rows below slide down.
  - **Glow:** a border colour and shadow transition, about 1.2 s out.
  - **Cursor:** absolutely positioned over the section. It moves with a transform transition of about 0.6 s, eased, to the centre of its target's element, measured with refs. `down` scales it to 0.9 and shows a ring spreading out.
  - **Clock:** rolls forward like the level. When the loop restarts (from "Wed 19:30" back to "Tue 21:44", while the window is closed) it fades out and in instead of rolling backwards.
- [ ] **Step 3: The lines beside the window.** Keep the layout of today's `AppPicture.astro`: the three columns at `md`, and both pairs of lines below the window on phones. Each side's slot gets a fixed minimum height, the height of its longest version from `LINES` and `STILL_LINES`, so nothing moves. The lines crossfade as one block when `part` changes.
